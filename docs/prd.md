## 2. 背景与问题定义
当前 K12 数字学习产品普遍存在以下问题：
1. 内容组织依赖固定题库，覆盖面受限，无法快速适配学生的临时问题和跨学科探索。
2. 学习流程以“题目-答案”为主，知识结构不透明，学生难以理解“为什么错”和“下一步学什么”。
3. 大多数系统只关注答题结果，缺少对学习状态的过程性识别，导致疲劳、挫败和低效学习无法被及时处理。

Prism 的 MVP 目标是在一个统一的专注空间内，将“知识探索、笔记沉淀、状态感知、主动助学”整合为连续体验，降低学习中断成本并提升学习完成度。

## 3. 产品目标与非目标
### 3.1 产品目标
1. 支持文本或图片输入，自动生成结构化知识图谱，减少学生从问题到知识框架的转换成本。
2. 通过导图与笔记联动，帮助学生从“点状理解”过渡到“结构化掌握”。
3. 在用户授权前提下，低打扰识别学习状态并触发温和干预，提升学习连续性。
4. 在 MVP 阶段形成可测、可验收、可迭代的产品与工程闭环。

### 3.2 非目标
1. 不建设教师端备课与班级运营系统。
2. 不在 MVP 提供学科全量课程体系或完整教研内容库。
3. 不承诺医疗级情绪识别，仅提供学习场景下的辅助性状态标签。
4. 不在 MVP 引入复杂社交玩法或排行榜机制。

## 4. 目标用户与核心场景
### 4.1 目标用户
1. 小学高年级至高中学生。
2. 主要使用平板进行课后自学、错题复盘、知识拓展。
3. 具备基础数字设备使用能力，接受 AI 辅助学习方式。

### 4.2 核心场景
1. 主动探索场景：学生输入“新知识主题”，快速获得可导航的知识图谱和分层讲解。
2. 错题攻克场景：学生上传题目图片，系统抽取考点并重建对应知识路径。
3. 学习受阻场景：学生长时间停留且状态波动，系统给出简短、可执行的助学建议。

## 5. MVP 范围与功能清单
### 5.1 In Scope
1. Focus Space 单页面沉浸式学习工作区。
2. 文本/图片统一入口的结构化知识生成。
3. React Flow 知识导图渲染与节点交互。
4. Markdown 笔记板与节点联动高亮、流式讲解补全。
5. 用户授权后的周期性学习状态检测。
6. Prism Orb 主动/被动交互与干预触发。
7. 隐私授权、最小化采集、图像不落盘策略。

### 5.2 Out of Scope
1. 教师端、家长端和多角色管理后台。
2. 离线模型推理与本地端侧大模型部署。
3. 学校级 SIS/LMS 深度对接。
4. 完整题库运营系统与内容审核工作台。

## 6. 信息架构与交互流程（Focus Space）
### 6.1 页面布局
1. 顶部状态栏：左侧品牌与工作区标识，右侧状态指示 `AI Vision Active`。
2. 左侧主视图（60%）：万物探索栏、上传入口、知识导图区。
3. 右侧主视图（40%）：智能独立笔记板（Markdown/公式渲染）。
4. 右下角悬浮层：Prism Orb 智能助教入口。

### 6.2 关键用户价值路径
1. 用户输入文本问题或上传图片。
2. 系统统一生成 `KnowledgeOutlineJSON` 并渲染导图。
3. 用户点击导图节点，右侧定位对应 `NoteSection`，缺失内容时触发流式生成。
4. 授权状态下，系统周期产出 `VisionStateJSON`。
5. 满足干预阈值时生成 `InterventionEvent`，由 Prism Orb 发起提示与辅助动作。

## 7. 核心功能需求（FR）
### FR-01 全域知识探索与结构化生成
#### 目标
支持文本与图片两类输入，输出统一结构化知识大纲并可视化。

#### 前置条件
1. 用户已进入 Focus Space。
2. 网络可用，模型服务可调用。
3. 图片输入需获得相册或拍照权限。

#### 主流程
1. 用户在探索栏输入文本或上传题目图片。
2. 系统根据输入类型调用文本/视觉模型。
3. 服务端产出统一结构 `KnowledgeOutlineJSON`。
4. 前端渲染导图并将探索栏吸顶。
5. 右侧笔记板生成导论或首个节点解析。

#### 异常流程
1. 识别失败：提示“解析失败，请重试或改用文字描述”。
2. 模型超时：提示“响应超时，可重试”，保留用户输入。
3. 输出结构不完整：进入降级模式，仅展示线性大纲。

#### 输入输出
1. 输入：`text` 或 `image/*`。
2. 输出：`KnowledgeOutlineJSON`，并触发默认 `NoteSection` 生成。

#### 验收标准
1. 文本输入后可生成可交互导图。
2. 图片输入后可提取核心考点并构建导图。
3. 导图至少包含根节点与一级子节点。

### FR-02 联动式智能笔记工作区
#### 目标
将导图节点与讲解内容双向绑定，支持用户编辑沉淀。

#### 前置条件
1. 已存在导图数据。
2. 右侧笔记板已初始化。

#### 主流程
1. 用户点击左侧导图节点。
2. 系统定位对应 `NoteSection` 并滚动高亮。
3. 若节点内容不存在，触发流式讲解生成。
4. 用户可对内容进行 Markdown 编辑与保存。

#### 异常流程
1. 节点无可映射 ID：提示“节点内容暂不可用”，支持手动创建笔记。
2. 流式中断：保留已生成片段并提供“继续生成”。

#### 输入输出
1. 输入：`node_id`、用户编辑内容。
2. 输出：更新后的 `NoteSection`，含 `generated_by` 标识。

#### 验收标准
1. 节点点击后 1 次交互内可到达对应笔记段落。
2. 支持加粗、代码块、LaTeX 公式渲染。
3. 用户编辑内容可覆盖 AI 初稿并持久化。

### FR-03 多模态学习状态监测
#### 目标
在用户授权下，低打扰识别专注度、情绪和坐姿标签。

#### 前置条件
1. 用户完成隐私告知并授权摄像头。
2. 监测配置开启，周期默认为 15 秒。

#### 主流程
1. 前端按周期低分辨率抽帧。
2. 抽帧数据发送至视觉模型进行标签提取。
3. 系统接收并记录 `VisionStateJSON`。
4. 标签用于实时状态判断与干预触发，不保存原始图像。

#### 异常流程
1. 未授权：系统关闭监测，仅保留手动助教能力。
2. 视觉服务不可用：暂停监测并提示“状态识别暂不可用”。
3. 置信度过低：不触发主动干预，仅记录低置信标签。

#### 输入输出
1. 输入：摄像头抽帧、`ConsentState`。
2. 输出：`VisionStateJSON`（仅标签，不含原始图像）。

#### 验收标准
1. 授权后可持续输出状态标签。
2. 撤销授权后 1 次轮询周期内停止采集。
3. 全流程不落盘保存实体图像。

### FR-04 Prism Orb 主动助学助手
#### 目标
提供常驻、低干扰、可主动触发的学习辅助交互。

#### 前置条件
1. Prism Orb 组件已加载。
2. 主动干预依赖 FR-03 状态标签。

#### 主流程
1. 被动模式：用户点击 Orb，输入语音或文本问题。
2. 主动模式：当连续两次检测到受挫或坐姿异常时触发提醒。
3. 系统生成干预话术与下一步动作建议。
4. 用户接受后，系统执行简化讲解、前置知识回顾或变式题生成。

#### 异常流程
1. 触发抖动：命中冷却时间时不重复弹窗。
2. 用户拒绝干预：记录 `accepted=false` 并延后再触发。

#### 输入输出
1. 输入：用户问题、`VisionStateJSON`。
2. 输出：`InterventionEvent`、对话结果、笔记区新增内容。

#### 验收标准
1. 用户可随时唤起 Orb 对话。
2. 连续两次命中异常标签才触发主动干预。
3. 干预后可形成可执行学习动作。

## 8. 非功能需求（NFR）
### 8.1 性能
1. 文本探索首次结构化结果目标在 3-8 秒内返回。
2. 图片探索首次结构化结果目标在 5-12 秒内返回。
3. 导图节点点击到笔记定位目标小于 500ms。

### 8.2 可用性
1. 核心链路具备超时重试与降级文案。
2. 外部模型不可用时，保留手动笔记与基础对话能力。

### 8.3 安全与权限
1. 摄像头权限默认关闭，显式授权后才可开启监测。
2. 权限状态可随时撤销，撤销后立即生效。

### 8.4 兼容与可访问性
1. 适配平板横屏主流分辨率。
2. 提供关键文本提示与状态反馈，避免仅依赖颜色表达。

### 8.5 可观测性
1. 记录请求耗时、错误码、干预触发率、用户接受率。
2. 日志不含原始图像和可逆生物特征数据。

## 9. 数据与隐私合规
### 9.1 数据最小化原则
1. 仅采集实现功能所需的最小字段。
2. 学习状态监测仅输出标签，不保存实体照片。

### 9.2 授权与告知
1. 首次启用监测前展示用途、频率、存储策略和撤销方式。
2. 授权状态由 `ConsentState` 统一管理并可追踪版本。

### 9.3 存储与删除策略
1. 原始抽帧数据仅作瞬时处理，不写入本地或云端持久存储。
2. 结构化标签与事件日志按最短必要周期保留。
3. 用户撤销授权后停止新采集，并按策略清理历史标签。

### 9.4 对外合规口径
1. 仅用于学习辅助，不用于身份识别或画像营销。
2. 不向第三方共享可识别个人身份的学习状态原始数据。

## 10. 指标与评估（轻量）
### 10.1 使用过程指标
1. 探索转化率：发起探索后成功生成导图的比例。
2. 联动使用率：导图点击触发笔记定位的比例。
3. 干预接受率：主动干预后用户接受建议的比例。

### 10.2 学习效率观察项
1. 单次学习会话完成度。
2. 同类知识点二次求助频率变化。
3. 错题复盘后再次错误率变化趋势。

### 10.3 系统健康指标
1. 模型请求成功率与超时率。
2. 关键路径响应时长分布。
3. 状态识别置信度分布与误触发率。

## 11. 里程碑与交付计划
1. M0（第 1 周）：需求冻结、交互稿冻结、接口契约评审。
2. M1（第 2-4 周）：完成 FR-01 与 FR-02，形成可用学习主链路。
3. M2（第 5-6 周）：完成 FR-03 与 FR-04，打通状态监测与主动干预。
4. M3（第 7 周）：稳定性修复、UAT 回归、发布准备。

## 12. 验收标准（UAT）
| 编号 | 场景 | 操作步骤 | 预期结果 |
| --- | --- | --- | --- |
| UAT-01 | 文本探索 | 输入新知识主题并提交 | 生成 `KnowledgeOutlineJSON`、渲染导图、生成首屏笔记 |
| UAT-02 | 图片探索 | 上传错题图片并提交 | 提取核心考点并重建导图 |
| UAT-03 | 导图联动 | 点击任一知识节点 | 笔记区自动滚动并高亮对应段落 |
| UAT-04 | 流式讲解 | 点击无现成内容节点 | 笔记区按流式补全解释内容 |
| UAT-05 | 状态监测授权 | 授权摄像头并等待周期执行 | 周期输出 `VisionStateJSON` |
| UAT-06 | 状态监测降级 | 拒绝或撤销摄像头权限 | 系统不报错，关闭监测并保留手动助教 |
| UAT-07 | 主动干预触发 | 连续两次命中受挫或坐姿异常 | 触发 `InterventionEvent` 并显示干预提示 |
| UAT-08 | 主动干预阈值 | 仅一次命中异常标签 | 不触发主动干预 |
| UAT-09 | 隐私约束 | 执行监测链路并检查日志/存储 | 无原始图像落盘，仅有标签与事件日志 |
| UAT-10 | 失效场景 | 模拟模型超时或失败 | 出现降级文案与重试入口，用户输入不丢失 |

## 13. 风险与应对
1. 风险：模型输出不稳定导致知识结构质量波动。
应对：增加输出校验与结构修复层，异常时降级为线性大纲。
2. 风险：视觉标签误判导致干预不准确。
应对：采用连续命中阈值与冷却机制，降低误触发。
3. 风险：用户对摄像头功能敏感导致授权率低。
应对：提供透明告知、可撤销开关、未授权可用的替代路径。
4. 风险：外部模型依赖引发成本和可用性波动。
应对：设置超时、重试、备用模型与频率控制策略。
