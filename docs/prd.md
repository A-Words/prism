## 1. 项目背景与产品定位

### 1.1 背景与机会

当前主流 AI 解题工具更擅长“快速给答案”，但对高中数学学习更关键的过程支持——例如题型识别、前置知识判断、思路拆解、错因定位与回补——通常不够稳定，也不够可解释。UNESCO 的生成式 AI 教育指导强调，教育场景中的 AI 应坚持以人为中心、由人控制，并与学习目标、年龄阶段、目标知识类型和问题类型匹配；OECD 则将形成性评价描述为一个持续循环：设定学习目标、诊断学习状态、提供反馈，并据此调整下一步教学。

因此，**Prism 不定位为“搜题 + 题解”工具，而定位为“数学学习导航系统”**：它通过路径图显化专家思维，通过诊断与回补形成闭环，并将学生从“看答案”转向“走路径”。这一方向也与 EEF 对掌握式学习的总结一致：内容被拆为清晰单元，学习者达到较高掌握门槛后再进入下一层，未达标者获得额外支持。

### 1.2 产品定位

* **产品名称**：Prism（数学学习导航）
* **核心定位**：把“题目”转成解题路径，把“目标知识”转成学习路径，并依据学生作答动态回补前置知识
* **目标学段**：高中数学
* **优先模块**：代数、函数、导数、不等式、三角、解析几何中的高频基础模块
* **MVP 核心主线**：AI 学习路径生成 → 节点学习 / 自测 → 错因诊断 → 前置回补 → 同类题验证

### 1.3 一句话定义

> 一个把“题目”转化为解题路径、把“学习目标”转化为学习路径、并依据学生作答动态回补前置知识的高中数学 AI 学习导航系统。
> 本版 PRD 重点：以“AI 学习路径生成”作为核心主线，并与“解题路径图”“练习诊断与回溯”形成完整闭环。

### 1.4 产品概要

| 项目     | 内容          | 项目   | 内容                     |
| ------ | ----------- | ---- | ---------------------- |
| 产品代号   | Prism       | 面向对象 | 高中学生 / 数学教师 / 家长（查看进度） |
| 核心版本目标 | 完成 MVP 闭环验证 | 主要场景 | 目标输入生成路径、错题回补、同类题验证    |
| 产品原则   | 过程支持 > 直接代答 | 文档读者 | 产品、设计、算法、前后端、教研        |

### 1.5 产品机会判断

> 如果系统能够证明“路径图 + 回补”比“直接看标准答案”更能提升后续同类题正确率，那么该产品将具备清晰的教育价值与差异化。

### 1.6 当前原型与改版方向

| 当前原型状态       | V1.0 改造目标                       |
| ------------ | ------------------------------- |
| 首页以功能入口为主    | 首页改为“继续学习 / 今日任务 / 当前薄弱点”       |
| 学习路径页偏知识点浏览  | 学习路径页改为“目标输入 → 路径生成 → 当前节点执行”   |
| 解题路径页更像可视化题解 | 强化思维动作节点、互动提示与易错分支              |
| 练习诊断页停留在错误说明 | 加入“立刻补救 / 回到前置知识 / 再做一题”三种下一步动作 |

## 2. 用户、场景、目标与非目标

### 2.1 目标用户

| 用户角色 | 核心诉求                | 典型使用频率        |
| ---- | ------------------- | ------------- |
| 高中学生 | 知道自己该学什么、错在哪、下一步怎么补 | 高频 / 每周 3–7 次 |
| 数学教师 | 获取讲评框架、错因分布、分层补救建议  | 中频 / 每周 1–3 次 |
| 家长   | 查看路径进度、薄弱点与回补完成情况   | 低频 / 每周 1–2 次 |

### 2.2 典型使用场景

1. 学生输入“我想学导数应用”，系统自动识别目标类型、推断先修链、生成学习路径，并给出建议起点。
2. 学生遇到一道题，不直接看标准解，而是查看解题路径图，按节点尝试并接受分步提示。
3. 学生做练习时答错，系统定位错因并自动回溯到需要回补的前置节点，再给 2–3 道微练习。
4. 教师课后查看班级高频错因，直接使用系统生成的路径图作为讲评骨架。

### 2.3 产品目标（Goals）

| 目标         | 说明                                        |
| ---------- | ----------------------------------------- |
| G1. 建立学习闭环 | 让学生在“路径生成—学习—自测—诊断—回补—验证”中持续推进，而不是跳进跳出功能页 |
| G2. 提升可解释性 | 所有推荐都应能回答：为什么从这里开始？为什么回退到这一层？为什么给这道题？     |
| G3. 控制答案泄露 | 默认以思路节点、提示和检查点替代完整标准答案，避免沦为代做工具           |
| G4. 证明学习收益 | 重点验证：路径式支持是否提升后续同类题正确率与回补后的复测通过率          |

### 2.4 非目标（Non-goals）

* 不在 MVP 阶段覆盖整个高中数学全量知识体系
* 不在学生模式默认展示完整标准答案与完整长链推导
* 不将 LLM 作为唯一逻辑引擎；先修关系、回补规则、掌握度更新必须有结构化规则支撑
* 不以拍照搜题和答案速度作为核心卖点

### 2.5 成功指标（North Star + Supporting Metrics）

| 指标    | 定义                          | 首阶段目标   |
| ----- | --------------------------- | ------- |
| 北极星指标 | 学习路径完成率（至少完成 1 条路径中的 3 个节点） | ≥ 35%   |
| M1    | 路径生成后 24 小时内启动首个节点学习的比例     | ≥ 60%   |
| M2    | 回补后复测通过率                    | ≥ 55%   |
| M3    | 同类题正确率提升（看路径组 vs 直接答案组）     | +10% 以上 |
| M4    | AI 推荐可解释点击率（查看“为什么推荐”）      | ≥ 30%   |
| M5    | 7 日留存（有明确学习目标用户）            | ≥ 20%   |

| ---------- | ---------------- | --------------------- |
| 首页 / 学习仪表盘 | 承接当前学习任务与薄弱点     | 继续学习、开始路径、进入诊断        |

## 4. 核心用户旅程

### 4.1 Journey A：从“我想学什么”开始

1. 用户在学习路径页输入目标，例如“我想学导数应用”。
2. 系统识别输入类型：知识主题 / 题型能力 / 薄弱修复 / 备考目标。
3. 系统给出路径摘要卡：预计时长、建议起点、节点数、生成依据。
4. 用户选择“快速生成”或“先做 3 题起点测试”。
5. 系统进入当前推荐节点，展示“学什么、学会标准、常见错误、微练习”。
6. 若用户测试未过，系统回退到前置节点，并记录该薄弱点。
7. 用户回补完成后，系统投放 1 道同类验证题，验证是否真正掌握。

### 4.2 Journey B：从“一道做错的题”开始

1. 用户在练习诊断页完成作答。
2. 系统返回四段式反馈：**错在哪里 / 为什么错 / 要补哪一层 / 现在就补**。
3. 系统自动生成知识回溯路径图，定位回补节点。
4. 用户进入回补内容并完成微练习。
5. 系统给出验证题，若通过则标记该节点为“已修复”；若未通过则继续回退。

## 5. 详细功能需求

## 5.1 模块 A：首页 / 学习仪表盘

**设计原则**：首页不是功能入口墙，而是任务驱动页面。用户打开后应立刻知道“我现在在哪、我该做什么、为什么是这一步”。

### 首页需求清单

| 编号   | 需求项                          | 优先级 | 验收标准                        |
| ---- | ---------------------------- | --- | --------------------------- |
| A-01 | 展示“继续学习”主卡，优先返回上次未完成的学习节点    | P0  | 存在进行中路径时，首页首屏展示当前节点与 CTA 按钮 |
| A-02 | 展示“今日任务”与推荐学习时长              | P0  | 可根据路径进度生成 1–3 个今日任务         |
| A-03 | 展示“当前薄弱点”与判定理由               | P0  | 至少显示最近 7 天高频薄弱点及其来源         |
| A-04 | 展示最近诊断结果与一键回补入口              | P0  | 用户可从首页直接进入回补节点              |
| A-05 | 保留三大工具入口（解题路径 / 学习路径 / 练习诊断） | P1  | 入口保留但视觉优先级低于任务主卡            |

---

## 5.2 模块 B：解题路径图

**设计原则**：默认不直接给完整题解，而以“思维动作节点 + 易错分支 + 互动尝试”来支持学习过程。IES 的数学问题解决实践指南强调，教学应帮助学生使用视觉表征、监控与反思解题过程，并接触多种解题策略，而不只是接收最终答案。

### 解题路径图需求清单

| 编号   | 需求项                        | 优先级 | 验收标准                    |
| ---- | -------------------------- | --- | ----------------------- |
| B-01 | 支持文本 / LaTeX 输入题目          | P0  | 用户可输入数学表达式，系统完成解析       |
| B-02 | 生成题目画像：学段、题型、知识点、难度、前置能力   | P0  | 返回结构化卡片，可被后续诊断复用        |
| B-03 | 生成 5–8 个主路径节点，节点名以思维动作命名   | P0  | 节点名称不应仅是“运算步骤”，而应体现判断逻辑 |
| B-04 | 展示易错分支（如忽略定义域、漏讨论参数）       | P0  | 至少列出 2 个高频错误分支          |
| B-05 | 在关键节点插入“我来试一步”互动点          | P1  | 用户可作答，系统只反馈是否走对方向       |
| B-06 | 学生模式默认仅展示节点与提示；教师模式可展开完整讲解 | P1  | 不同角色展示层级不同              |
| B-07 | 若用户在节点尝试失败，写入薄弱点并关联到学习路径   | P0  | 失败行为可在诊断页与首页被追踪         |

---

## 5.3 模块 C：AI 学习路径生成（本版核心）

**设计原则**：这一页不再是知识点浏览页，而是“告诉我你想学什么，AI 为你生成路径”。依据 EEF 对掌握式学习的总结，学习内容应被拆成较小单元，并以明确标准决定是否进入下一层；常见做法是以约 80% 或更高掌握度作为升级门槛，未达标者得到额外支持。([EEF][2])

### AI 学习路径生成需求清单

| 编号   | 需求项                                | 优先级 | 验收标准                       |
| ---- | ---------------------------------- | --- | -------------------------- |
| C-01 | 顶部目标输入框：支持自然语言输入学习目标               | P0  | 可识别知识主题、题型能力、薄弱修复、备考目标四类意图 |
| C-02 | 支持用户选择基础水平（从零开始 / 有一点基础 / 冲题型）     | P0  | 不同基础生成不同起点与节点颗粒度           |
| C-03 | 支持用户选择目标层级（理解概念 / 会做基础题 / 冲综合题）    | P0  | 不同目标层级影响路径长度与验证题难度         |
| C-04 | 提供“快速生成 / 先做 3 题起点测试”两种模式          | P0  | 精准模式需在 3 题内确定推荐起点          |
| C-05 | 生成路径摘要卡：目标、预计时长、节点数、当前建议起点、生成依据    | P0  | 摘要卡需带“为什么从这里开始”的解释         |
| C-06 | 页面采用三栏布局：路径目录 / 主路径图 / 当前节点学习卡     | P0  | 路径图与执行区同时可见，无需反复跳页         |
| C-07 | 每个节点必须包含“学什么 / 学会标准 / 常见错误 / 前置节点” | P0  | 节点信息完整且结构化                 |
| C-08 | 支持仅展开主干路径，补救分支按需动态出现               | P0  | 首屏不得一次暴露全量图谱               |
| C-09 | 支持“开始学习 / 直接自测 / 展开前置知识 / 标记稍后再学”  | P1  | 学习卡提供明确动作                  |
| C-10 | 节点完成后自动进入验证，未通过则触发回退规则             | P0  | 同一节点必须有通过与未通过两条后续路径        |

## 5.4 模块 D：练习诊断与知识回溯

**设计原则**：诊断页不止要解释“为什么错”，更要明确“接下来做什么”。OECD 将高质量形成性评价描述为学习目标、诊断、反馈与教学调整的连续过程，并强调学生应有机会理解并实际使用反馈推动学习前进。

### 练习诊断与回溯需求清单

| 编号   | 需求项                                   | 优先级 | 验收标准            |
| ---- | ------------------------------------- | --- | --------------- |
| D-01 | 答题后输出四段式反馈：错在哪里 / 为什么错 / 要补哪一层 / 现在就补 | P0  | 四段均需完整展示        |
| D-02 | 错因标签化：概念错误 / 公式误用 / 条件识别错误 / 计算稳定性不足  | P0  | 每道错题至少命中 1 个主标签 |
| D-03 | 生成知识回溯路径图，并高亮当前建议补救节点                 | P0  | 回溯图必须含“推荐起点”    |
| D-04 | 为补救节点投放 2–3 道微练习与 1 道回测题              | P0  | 补救内容量固定且节奏短     |
| D-05 | 提供“开始补救 / 回到前置知识 / 再做一题验证”三种 CTA      | P0  | 用户能明确下一步动作      |
| D-06 | 补救结果实时更新到知识状态、首页任务与路径目录               | P0  | 三个页面状态一致        |

## 6. AI 与数据逻辑

### 6.1 核心模型分层

| 层     | 职责                    | 建议实现方式            |
| ----- | --------------------- | ----------------- |
| 题目理解层 | 题型识别、知识点抽取、难度判断、表达式解析 | 规则 + 模型联合，优先结构化输出 |
| 教育认知层 | 知识—能力混合图谱、前置关系、易错规则库  | 图谱 + 规则引擎         |
| 学生建模层 | 知识状态、错误模式、路径进度、回补历史   | 轻量知识追踪 / 掌握度更新    |
| 交互生成层 | 路径图文案、提示语、反馈表达、鼓励语    | LLM 负责自然语言与柔性交互   |

### 6.2 知识—能力混合图谱

* 图谱节点不仅包含知识点（如“导数概念”“基本不等式”），还包含能力动作（如“识别分类讨论触发条件”“检查定义域”“使用导数符号表”）
* 边类型至少包括：先修、包含、易混淆、常见错误来源、可验证题型
* 学生状态记录粒度建议到“节点 × 能力动作”级别，而非只到章节级别

### 6.3 学习路径生成逻辑

1. **意图识别**：将输入归类为知识主题、题型能力、薄弱修复、备考目标
2. **候选起点生成**：从知识图谱中召回相关节点，并结合用户基础水平与历史薄弱点筛选候选起点
3. **路径裁剪**：优先保留 4–7 个主干节点；补救分支按需动态添加
4. **摘要解释生成**：给出预计时长、起点、节点数和推荐理由
5. **执行阶段状态更新**：每完成一节点或一次测验，更新掌握度与后续推荐

### 6.4 掌握度与回退规则

| 规则项   | 建议                                             |
| ----- | ---------------------------------------------- |
| 掌握阈值  | 单节点完成 2–3 道微练习 + 1 道验证题，总体正确率 ≥ 80% 视为通过       |
| 回退深度  | 优先只回退 1 层；若连续两次未通过，再回退 2 层                     |
| 回退依据  | 优先根据错因标签决定回退方向，例如“求导错误”回退到求导法则，“符号表错误”回退到单调性判定 |
| 推荐透明度 | 每次回退都必须显示一句可读解释                                |

### 6.5 AI 输出约束（防止沦为代答工具）

* 学生模式默认输出：节点、提示、检查点、易错分支，不直接展示完整标准答案
* 完整长解仅在教师模式或用户主动逐层展开后可见
* 若用户多次直接索要答案，系统优先返回“你现在缺哪一步”的提示而非直接代做
* 重要结论节点需带条件检验提示，例如定义域、参数范围、边界可取性

## 7. 交互与内容策略

### 7.1 页面文案原则

* 少用抽象命名，多用学生可理解的动作语言
* 所有 AI 推荐都尽量回答“为什么推荐我学这个”
* 诊断文案优先给出可行动建议，避免空泛鼓励
* 节点命名以“先判断什么 / 为什么这一步 / 这里最容易错什么”为核心

### 7.2 学习路径页推荐布局

| 区域    | 内容                                |
| ----- | --------------------------------- |
| 顶部输入区 | 我想学什么 + 我的基础 + 我的目标 + 生成路径 / 起点测试 |
| 路径摘要卡 | 目标、时长、节点数、当前起点、生成依据               |
| 左栏    | 路径目录：节点状态、前置 / 后续关系、推荐节点高亮        |
| 中栏    | 主路径图：主干链条 + 按需展开的补救分支             |
| 右栏    | 当前节点学习卡：学什么、学会标准、微练习、开始学习 / 直接自测  |

### 7.3 非功能要求

| 项     | 要求                                                                                        |
| ----- | ----------------------------------------------------------------------------------------- |
| 性能    | 路径生成首屏结果 ≤ 8 秒；单次诊断反馈 ≤ 5 秒                                                               |
| 一致性   | 首页、路径页、诊断页中的节点状态必须一致                                                                      |
| 可解释性  | 所有路径推荐与回退都应能生成自然语言解释                                                                      |
| 审计    | 保留题型识别、节点推荐、错因归因、掌握度更新的日志                                                                 |
| 隐私与合规 | 学生个人学习数据仅用于学习支持，不用于不透明的高风险自动决策；这一方向与 UNESCO 对教育中 GenAI 的人本、透明与适切使用原则一致。|

## 8. 指标、里程碑与风险

### 8.1 MVP 验证假设

* **H1**：学生愿意使用“输入我想学什么 → 生成路径”的入口，而不是只搜索知识点
* **H2**：路径式支持相较于直接看答案，能够提高后续同类题正确率
* **H3**：四段式诊断 + 立即补救，能够提升回补后复测通过率

### 8.2 实验设计建议

| 实验    | 设计                                         |
| ----- | ------------------------------------------ |
| A/B-1 | 同类题学习对照：A 组看标准答案；B 组看路径图 + 节点提示，比较后续迁移题正确率 |
| A/B-2 | 学习路径页入口：搜索知识点页 vs 目标输入生成页，比较路径启动率          |
| A/B-3 | 诊断结果页：只有错因讲解 vs 错因 + 立即补救，比较回补完成率          |

### 8.3 里程碑建议

| 阶段      | 周期    | 交付物                                         |
| ------- | ----- | ------------------------------------------- |
| Phase 1 | 2–3 周 | 知识—能力图谱最小集合（导数应用 / 基本不等式 / 一元二次不等式）与首页任务化改造 |
| Phase 2 | 3–4 周 | AI 学习路径生成页、起点测试、节点学习卡、路径状态流转                |
| Phase 3 | 3–4 周 | 诊断—回补—验证闭环、实验埋点、首轮 A/B 测试                   |
| Phase 4 | 2 周   | 解题路径互动化、教师模式初版、文案打磨与性能优化                    |

### 8.4 主要风险与应对

| 风险            | 说明           | 应对                            |
| ------------- | ------------ | ----------------------------- |
| 路径图有展示感但无学习收益 | 用户看图但不参与学习动作 | 强化互动点、微练习与验证题设计，并用 A/B 测试证明价值 |
| 回补规则不准        | 错因归因与回退层级不匹配 | 先做人审规则库，再逐步引入模型学习             |
| 图谱维护成本高       | 高中数学跨章节复用复杂  | 先做高频模块的 DAG，不追求一步到位           |
| 产品滑向搜题        | 完整答案暴露过多     | 学生模式默认关闭长解，分层提示优先             |

## 9. 附录

### 9.1 外部依据（用于产品原则）

本 PRD 的若干产品原则参考了公开教育研究与政策材料，主要用于支持以下方向：

* **以人为中心的教育 AI**：UNESCO 强调 GenAI 在教育中应由人控制、与年龄和学习目标匹配，并促进高阶思维与责任归属。
* **形成性评价闭环**：OECD 将高质量形成性评价概括为学习目标、诊断、反馈、教学调整的连续过程，并强调反馈应被学生真正使用。
* **掌握式学习**：EEF 将 mastery learning 描述为“分单元、设门槛、未达标则补救”的学习推进方式，常见门槛约为 80% 或更高。
* **可视化与多策略问题解决**：IES 数学问题解决实践指南强调视觉表征、监控反思与多策略暴露。

### 9.2 当前待确认问题（Open Questions）

* MVP 首批覆盖哪些具体专题最能验证路径价值？建议先从**导数应用、基本不等式、一元二次不等式**开始
* 起点测试题库是否由教研人工标注，还是由模型生成后人工审校
* 解题路径图是否在学生端支持拍照输入，或先只做文本 / LaTeX
* 教师模式在 MVP 是否要进入范围，还是作为 Phase 4 的增强项
* 路径节点的掌握阈值是否统一 80%，还是按主题动态设定

---

## 结论

**Prism 的产品价值不在“替学生做题”，而在于把数学学习中最难被显化的部分——路径、卡点、回补——做成可视化、可执行、可追踪的学习流程。V1.0 的关键，不是做更多功能，而是把“AI 学习路径生成”真正做成产品主线。**
